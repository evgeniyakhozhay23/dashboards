
# Дашборд приложения ленты сообщений и мессенджера
### Источник
Karpov Courses, курс "Симулятор Аналитика", https://karpov.courses/simulator

Данные с 02.05.2026 до текущего дня (обновляются в режиме реального времени). Данные предоставлены в рамках курса, хранятся в Clickhouse.

### Структура данных
Провожу работу с данными стартапа приложения с лентой новостей (feed_actions) и мессенджером (message_actions). 

Таблица feed_actions - информация о действиях пользователей в приложении ленты новостей:
- user_id - идентификационный номер пользователя
- post_id - номер поста
- action - вид действия пользователя в ленте (категориальная переменная). Значения - like и view.
- time - дата и время действия пользователя в ленте новостей
- gender - пол пользователя
- age - возраст пользователя
- country - страна проживания пользователя
- city - город проживания пользователя
- os - операционная система устройства, с которого заходят в приложение. Значения: iOS, Android
- source - канал привлечение клиентов: ads (через рекламу), organic (самостоятельно)
- exp_group - группа пользователя для проведения эксперимента

Таблица message_actions - информация о пользователях мессенджера
- user_id - идентификационный номер пользователя
- receiver_id - идентификационный номер получателя
- time - дата и время отправки сообщения
- source - канал привлечение клиентов: ads (через рекламу), organic (самостоятельно)
- exp_group - группа пользователя для проведения эксперимента
- gender - пол пользователя
- age - возраст пользователя
- country - страна проживания пользователя
- city - город проживания пользователя
- os - операционная система устройства, с которого заходят в приложение
### Используемые инструменты
- Apache Superset
### Задание
В приложении есть две части: лента новостей (основная) и мессенджер. Необходимо составить дашборд, который описывает взаимодействие двух сервисов — ленты и сообщений. 
### Вопросы, которые решает дашборд
1. Какая у нашего приложения активная аудитория по дням, т.е. пользователи, которые пользуются и лентой новостей, и сервисом сообщений?
2. Сколько пользователей использует только ленту новостей и не пользуются сообщениями?
3. Существует ли взаимосвязь между интенсивностью потребления контента в ленте и частотой отправки сообщений?
4. Есть ли взаимосвязь между тем, как пользователи пришли в продукт, и тем, используют они все услуги приложения или только ленту?
5. Есть ли взаимосвязь между полом, страной проживания пользователя и типом операционной системы их устройства и склонностью к использованию всей экосистемы приложения или только ленты новостей?
6. В каких возрастных сегментах наблюдается самая высокая доля пользователей обеих частей приложения?
### Содержание дашборда
- Линейные графики DAU и MAU пользователей всего приложения и только ленты новостей
- Линейный график лайков и просмотров пользователей двух сервисов приложения в динамике
- Линейный график лайков и просмотров пользователей только ленты
- Столбчатая диаграмма с распределением пользователей по сервисам в зависимости от канала привлечения клиента
- Таблица с топом пользователей по количеству сообщений в мессенджере и их лайками и просмотрами
### Выводы
- Активная аудитория за день и за месяц обоих сервисов сократилась при увеличении активной аудитории только ленты. Следовательно, падает активность именно в мессенджере.
- Лайки и просмотры пользователей только новостной ленты возрастают, а динамика лайков и просмотров пользователей обоих сервисов нисходящая. Происходит падение активности в ленте, если пользуются мессенджером.
- Пользователи, привлеченные по рекламе, больше сосредоточены на использовании ленты, чем мессенджера.
- Нет явной взаимосвязи с возрастом пользователей и тем, пользуются ли они только одним сервисом или двумя.
